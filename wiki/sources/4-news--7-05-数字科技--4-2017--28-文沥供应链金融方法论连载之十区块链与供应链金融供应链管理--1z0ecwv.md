# 文沥供应链金融方法论连载之十——区块链与供应链金融（2017）

## 基本信息

- **发布**：公众号"供应链金融"（sinotf.com），2017-06-27，栏目 1083
- **作者**：杨宏涛（Eric Yang），[[文沥WelinkData]]（上海文沥信息技术有限公司）CTO，上海交通大学毕业，长期从事 Java 架构、供应链管理应用与供应链金融系统开发设计
- **性质**：技术厂商撰写的方法论 + 产品推广文章（为 SCF Gateway 预热），涉及自家产品的表述属**厂商口径**

## 核心论点

区块链底层技术（非对称加密、P2P 分布式存储、共识机制）与供应链系统长期要解决的数据交换、对账问题**同构**；区块链适合解决供应链金融中**多方协作（非两点）**的数据交互与共识问题。这是本文区别于同期信用/凭证视角文章的独特**技术架构视角**。

## 论证脉络

### 1. 供应链数据交换的两种架构

- **核心企业自建系统**（CS 结构 → 门户 → SaaS 云化）：将企业间数据交换转化为系统内部处理，但推广程度取决于核心企业对生态伙伴的掌控力；上下游企业协作多个伙伴时面临多系统割裂。适合紧密生态（如文沥供需链中分公司、控股/专营经销商管理）。
- **多系统间通讯**：国际主流为广义 EDI（EDI、ebXML、RosettaNet 标准文档交换），国内以 Web Service / API 为主。

技术演进史：EDI 从 VAN 发展到互联网，用非对称加密 + 加密签名 + 回执/重试保证安全性与不可抵赖性；EDI 在中国"水土不服"的原因是**实施成本偏高（作者自注："实际上现在区块链也有这个问题"）**叠加业务模式变化快。XML → Web Service → API 一路演进，API 实时简单易用但丢失了 EDI 的不可抵赖性与可追踪性。文沥的 [[文沥WelinkData|B2BGateway 和 API Gateway]] 即融合 EDI 与 API 两种技术，交易银行可用网关技术构建"交易银行网关"。

### 2. 对账与共识

各系统各自记账，长期运行后结果（应付款、库存等）出现差异，传统解法是定期对账：记录台账（流水账），**"有点类似区块链中后一块链指向前一块链"**；对账即找到两条链的分叉点后人工处理差异。供应链系统是**两点对账**，区块链是**多点对账**以解决共识问题。

### 3. 区块链在三类供应链融资中的协作映射

供应链金融分应收类、库存类、预付类。以保理为例：买方、卖方、金融机构三方协作，任何一方建系统都难以让其他方积极使用，中心化方案是中心管理机构建系统；区块链提供去中心化方案——业务台账逐笔上链，**"每个操作都是一方发起，对应一方确认，但相关方可以查看"**。货押融资（保兑仓）同理；预付类难点在征信与额度管理（作者预告另行讨论）。详见 [[区块链多方协作在三类供应链融资中的应用-文沥2017口径]]。

### 4. SCF Gateway 产品宣传（厂商口径，需存疑标注）

文沥"即将发布"的交易网关 SCF Gateway：部署于企业端，与金融机构业务系统交互，采用与区块链底层相同的非对称加密技术对内容加密、签名传输；支持非区块链场景（处理后数据放金融机构方）与区块链场景（R3、HyperLedger、以太坊等）下的分布记账和智能合约。文末自称"**全球首款区块链数据网关产品**"——此为厂商宣传话术。

### 5. 大数据供应链金融生态叙事

文末介绍文沥定位为"企业与业务伙伴、金融机构之间的数据桥梁"，宣称以业务/交易数据为基础的数据模型为金融机构提供**动态征信、实时评判真实贸易背景与运营健康、授信评估与自动化贷后预警**。此段与正文区块链分布式协作叙事存在切换，属厂商打包宣传。
