# 案例 | 区块链技术是如何解决供应链金融痛点的？（万联网，2019）

## 基本信息

- 发布：万联网，2019-12-21，转述自万联供应链金融智库（无作者署名）
- 核心对象：[[entities/壹诺金融]]（[[entities/布诺]] 基于自有知识产权区块链底层打造的供应链金融业务支撑平台）
- 证据强度：**弱**。准自述性质的平台宣传稿，无作者、无业务数据、无具体客户案例，处于"一般新闻/软文"层级。正文解决方案编号为 1、2、3、5（缺 4），编辑粗糙进一步降低可信度。

## 文章结构

### 一、供应链金融四大痛点

1. **信息无法打通，存在信息孤岛**：各级供应商与核心企业难以建设统一业务系统（如 ERP），数据壁垒导致信息流无法随商流、物流共同流转。
2. **信任无法自证、无法传递**：核心企业良好资信只能传递到一级供应商，其他环节供应商难以依靠核心企业信用背书融资。
3. **支付结算无法自动完成**：结算基于传统清结算方式且需欠款方主动发起，延期付款、拒绝付款风险无法消除。
4. **缺乏优质业务场景（商票不可拆分）**：商票只能完整背书转让、无法拆分，一级供应商缺乏服务其他供应商的融资意愿，核心企业信用无法向产业链下游传递。

详见 [[concepts/区块链供应链金融四大痛点框架-2019壹诺口径]]。

### 二、壹诺金融平台功能与架构（自述口径）

主要功能：实名认证、资产管理（应收账款/采购单/仓单的登记、拆分、流转）、在线融资、资金管控、数据溯源、账户系统、数据分析与预警。

系统架构分层：展现及能力输出层（PC 端 + SDK Clients）→ 应用层（客户关系管理、凭证管理、授信管理、业务管理、费用管理；"已构建应收账款融资业务场景，并开展运营"）→ 支撑层（认证授权、服务发现、容错、数据中心、配置中心、日志监控、缓存、MQ 等）→ 平台服务层（版本发布与镜像管理）；另含金融级安全体系设计与对外 API 对接（核心企业 ERP、银行网银/信贷/核心系统）。

### 三、区块链解决方案（编号缺 4）

1. 多中心集体维护共享账本，按预设权限共享业务信息，解决信息不对称；
2. 技术增信：实名制 + 邀请注册制 + 债务信息双方审核，宣称"确保贸易真实性"并实现核心企业信任无损传递；
3. 智能合约 + 银行内部账户管理体系，实现履约条件/方式/账期/金额上链与应收账款逐层自动结算；
5. 打造业务撮合平台，缓解中小企业融资难、融资贵。

智能合约自动结算详见 [[concepts/智能合约应收账款自动结算场景-2019壹诺口径]]。

## 关键判断与张力

- 本文宣称"确保贸易真实性"，却又自认是"信息撮合平台"，平台对链下贸易真实性的核验能力存疑（内部张力）。
- 与 [[concepts/区块链赋能供应链金融四大局限-2019宋华口径]] 形成观点张力：宋华质疑的上链前真实性问题，本文仅以"实名制+双方审核"一笔带过，论证强度不足。
- 只涉及应收账款/单证类资产上链，回避动产物理真实性问题，与 [[findings/动产上链瓶颈链圈共识判断-2019转述口径]] 相容。
