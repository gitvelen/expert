# 区块链技术在贸易融资中的应用及挑战（贸易融资资讯，2018）

## 来源说明

- 发布：2018-01-10，公众号"贸易金融"（sinotf.com）
- 署名作者：彭自顺、谢环球、万志丹，文思海辉技术有限公司
- 原始出处标注为 talkwithtrend（"来源：网友评论"实为署名文章转载，来源归属以此为准）
- 性质：区块链贸易融资产品开发方的**工程实践分享**，兼具技术文档性质与公司自述口径

## 核心内容

### 业务痛点（实践开发者视角）

- 贸易融资自偿性要求每笔业务严格核验凭据、资信调查、货物流通（市场/运输/储存）情况；单笔小、笔数多、手续多流程长
- 风控依赖"人"进行信息收集、比对、实地考察——"写在规章制度上易，落实在实际操作环节难"
- 区块链方案宣称：贷前/贷中/贷后全流程上链形成闭环，降人力成本、提升贸易背景真实性核验（"成本效益优势明显"为公司自述，无第三方验证）

### 数据隐私是首要瓶颈（本源最有价值原创点）

参与方扩展后（出口商 A1/A2/A3、进口商 Z1/Z2/Z3、开证行 B1/B2/B3、通知行 C1/C2/C3），A1 绝不允许商业数据被 A2/A3 看到——分布式数据分发与商业隐私冲突，"数据共享与隐私的平衡将是重要突破难点"。

### 混合加密的部分可见性方案

- 散列：SHA-1（业务编号/用户标识，可替换国密 SM3）
- 对称：AES 加密业务数据（可替换国密 SM4）
- 非对称：RSA 加密 AES key 分发给各方（可替换国密 SM2）
- 流程：业务数据 JSON 序列化 → AES 加密 → 查各方公钥 → AES key 分别用各方公钥加密 → 数据+密钥+通知队列写入合约；接收方用私钥解 key 再解数据

### 链上链下分层原则

- 区块链不适于高频交易与海量数据；入链数据应为高价值不可篡改数据，海量数据传统存储
- 历史数据归档"暂无很好解决办法"
- 区块链不擅前端交易处理，采用与银行行内单证/贸易融资系统接口对接模式

### 技术选型与部署

- 基础平台：HyperLedger Fabric（成员服务/区块服务/链码服务/事件服务/API 与 CLI）
- 部署：虚拟专有网 + 分级部署（骨干成员全节点 CA/order/peer + 云应用；大型成员 order/peer；特殊成员自行部署）
- 底座：IBM BAAS（基于 IBM LinuxONE），EAL 5+ 认证、安全服务容器 SSC、HSM 金钥保护、10x Hash/50x ECC 优化、7x 吞吐/减 82% 响应时间（厂商口径）
- 现实约束："完全去中心化在金融类应用中还存在困难"，需中心化节点支撑身份认证与快速接入
- 合约设计：用户业务加密公钥合约、业务数据合约、用户业务通知合约三类

## 证据强度分层

- Fabric 机制与加密方案描述：**较强**（原文级技术文档）
- 数据隐私瓶颈论证：**中**（工程经验，逻辑自洽但非实证）
- "革命性变化""成本效益优势明显"等：**弱**（公司自述，2018 乐观舆论口径，应降权处理）

## 内部张力与价值

全文同时存在"革命性/巨大规模效益"的乐观叙事与"隐私不得不突破、归档无好办法、去中心化实际困难"的工程清醒，是 2018 年区块链贸易融资叙事中少有的自曝瓶颈样本，对 [[区块链贸易融资叙事演进2016-2026]] 的技术实干者视角有校准价值；为 [[链上不可篡改与链下数据真实性边界]] 提供 2018 年工程侧方案补充；与 [[区块链有更好没有也可以论-2018口径]] 的"必要论/可选论"分歧可对照。
