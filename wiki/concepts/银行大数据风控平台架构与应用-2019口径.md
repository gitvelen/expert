# 银行大数据风控平台架构与应用（2019口径）

银行大数据风控平台是集大数据处理、OLAP 分析、在线/离线分析、数据挖掘、数据模型与可视化于一体的综合性信用评估平台（2019 年媒体口径）。其背景是传统基于历史借贷与财务数据的信用评估存在标准单一、结果滞后、无法覆盖"信用白户"三大缺陷。

## 银行大数据管理四大问题

1. 数据使用效率低：加工使用强依赖 IT 人员，无自助式数据服务；
2. 外部数据杂乱：微博、电商等外部数据源难以整理为真实准确的数据；
3. 数据类型复杂：非结构化数据（视频、音频、图片、邮件）占比大，传统 Oracle、SQL Server 难以支撑；
4. 数据孤岛：数据分散于各应用系统，跨系统综合搜索分析困难。（与 [[concepts/大数据在供应链金融的四维应用-2017口径]] 中的"信息孤岛"讨论同源）

## 数据治理五层分层

源数据 → 归档数据（细节数据）→ 整合数据（主题汇总数据集市）→ 指标数据 → 决策支持数据。

## 技术方案（愿景口径）

基于 Hadoop 分布式存储与云计算 + JAVA/J2EE 开发，融合结构化、半结构化、非结构化数据，宣称支持小时级部署、秒级查询与水平扩展。此为厂商化宣传口径，无实际案例验证。

## 风控四环节应用

贷前信审、反欺诈、贷后风险监测预警与催收、追偿清收；核心是关注客户在银行体系内外的负面信息（清单见 [[findings/银行行内外负面信息分类清单-2019口径]]）。

## 评价

低强度媒体综述证据，技术效果主张未经验证。与供应链场景端的大数据应用（[[concepts/大数据四项应用与五项条件-2017口径]]）构成 2017→2019 银行端与场景端对照线索。
