# 混合加密实现链上数据部分可见（2018 文思海辉口径）

针对联盟链数据全透明与商业隐私的冲突，文思海辉采用"对称加密数据 + 非对称加密分发密钥 + 散列标识"的混合方案，使链上数据仅对业务参与方可见。

## 算法选型（均预留国密替换路径）

| 用途 | 选用 | 替换 | 理由 |
|------|------|------|------|
| 散列（业务编号/用户标识） | SHA-1 | SM3 | 散列后利于做存储键值 |
| 对称加密（业务数据） | AES | SM4 | 加解密快，适合读写前后处理 |
| 非对称加密（AES key 分发） | RSA | SM2 | 密钥对特性适合给每个参与方各加密一份 key |

## 流程

**入链**：业务数据按指定 JSON 格式序列化 → AES 加密 → 从链上查询各方加密公钥 → AES key 分别用各方公钥加密 → 业务数据 + 各方密钥加密数据 + 通知队列写入合约。

**出链**：接收方查询通知队列获业务编号 → 取自己的 key 加密数据 → 取业务加密数据 → 私钥解 key → key 解业务数据。

## 合约支撑

用户业务加密公钥合约（存取业务加密公钥）、业务数据合约（加密数据与 key 管理，支持新加入参与方补发 key）、用户业务通知合约（通知队列任务）三类合约。
