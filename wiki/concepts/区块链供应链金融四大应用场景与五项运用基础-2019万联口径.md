# 区块链供应链金融四大应用场景与五项运用基础（2019 万联口径）

> 来源：万联供应链金融智库文章，经 [[entities/万联网]] 于 2019-12-21 发布。以下为该来源的**转述口径**，属观点性内容。

## 五项运用基础

1. 基于加密的可信数据
2. 基于存证的真实性证明
3. 基于共享账本的交易确权
4. 基于智能合约的合约执行
5. 基于通证（token）的信用拆解（共享）

目标：满足供应链上多元信息来源的相互印证与匹配，解决资金方对交易数据不信任的痛点。

## 四大应用场景

### 1. 可信数据与交易真实性证明

区块链+物联网+互联网结合供应链场景，多主体数据上链后凭不可篡改、可追溯的技术特性，加之多维度数据相互印证（采购数据与物流数据匹配、库存数据与销售数据印证、核心企业数据与下游链条数据核验）提升数据可靠性，降低信息不对称造成的流程摩擦。

### 2. 交易确权

形成不可篡改的权利账本，自动确认动产权利。典型机制：区块链对接核心企业 ERP 系统，实现应收账款的实时数字化确权，解决现实确权延时问题。

### 3. 智能合约

满足条件时货物、货权、资金、债权等资产自动且强制转移，并保障合约其他义务的执行；解决人工操作效率低、成本高、阻滞（不愿配合）与误操作风险。

### 4. 信用拆解（通证多级流转）

核心企业信用经 token 拆解逐级传递，持有 token 即证明与核心企业有合作关系，可凭核心企业信用背书融资。文中举例：某汽车制造商十几万家供应商中一级供应商仅 100 家，二三级供应商融资需求难以满足。此机制是 [[concepts/区块链数字资产凭证多级流转模式-2018金单口径]] 与 [[concepts/多层级信用传递与资产数字化上链-2018口径]] 在 2019 年的延续口径。

## 全链信息化前提论

该框架的**关键限定**：区块链应用的前提之一是全链信息化。现实中：

- 核心企业与一级供应商/经销商信息化水平较好，但链条上其他层级的中小企业信息化难以达到银行数据标准
- 不同主体采用异构信息管理系统时，信息传递缺乏一致性、连续性，形成信息孤岛，难以支持风险判断与真实性验证

这一限定与 [[concepts/区块链赋能供应链金融四大局限-2019宋华口径]] 的方向一致，也与 [[concepts/区块链溯源上链前数据真实性问题]] 相呼应：本文未解决上链前数据真实性问题。

## "信用自证/信用自增"论（弱证据）

原文称公开透明机制下机构相互监督、交易行为互相印证，将产生"信用自证"与"信用自增"的特殊信用增级现象。此说**缺乏机制论证**，属宣传性表述，引用时须标注为观点而非经核验事实。
