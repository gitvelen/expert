# 供应链数据交换架构与对账共识同构论（文沥2017口径）

## 定义

2017 年文沥 CTO 杨宏涛提出的技术架构视角：区块链底层技术（非对称加密、P2P 分布式存储、共识机制）所要解决的问题，与供应链系统长期要解决的**数据交换**与**对账/共识**问题同构；因此区块链的价值点在于供应链金融的**多方（非两点）协作**场景。

## 数据交换的两种架构

1. **核心企业自建系统**（CS 结构 → 门户 → SaaS）：把企业间数据交换变成系统内部处理，但推广依赖核心企业对生态伙伴的掌控力；上下游企业协作多个伙伴时面临多个无法整合的系统。适合紧密生态（分公司、控股/专营经销商管理）。
2. **多系统间通讯**：
   - 国际：广义 EDI（EDI、ebXML、RosettaNet 标准文档交换），从 VAN 发展到互联网，用非对称加密 + 签名 + 回执/重试保证安全与不可抵赖
   - 国内：Web Service → API 演进，实时、简单、易用，但丢失 EDI 的大批量交互、不可抵赖性、可追踪性优点

**关键自省**：EDI 在中国"水土不服"的原因是实施成本偏高叠加业务模式变化快——作者自注"实际上现在区块链也有这个问题"。这一表述与 2017 年同期的区块链乐观基调形成微妙反差，是该话语簇中少见的成本障碍自省。

## 对账与共识的同构

- 各系统各自记账，长期运行后应付款、库存等结果出现差异，传统解法是定期对账
- 台账即流水账，"有点类似区块链中后一块链指向前一块链"；对账即找到两条链的分叉点后人工处理差异
- 供应链系统对账是**两点对账**；区块链是**多点对账**以解决共识问题

## 定位与局限

- 这是 2017 年区块链+供应链金融话语簇（易见科技、东银商品交易中心等）中独特的**数据交换/对账视角**样本，区别于信用/凭证视角
- 属逻辑论证而非实证，无落地数据与案例验证；证据强度中等偏弱（专业公众号分析口径）
